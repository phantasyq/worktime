# Work Time v3.2.0 — календарь списаний

Адаптивное PWA для учёта рабочего времени на GitHub Pages с синхронизацией в личную Google Таблицу пользователя.

## Основные функции
- Единый календарь списаний с добавлением, редактированием, удалением и быстрым Jira-флагом прямо у каждой записи.
- Красная подсветка дней, в которых не все списания отмечены как списанные в Jira; зелёный Jira-статус для каждой отмеченной записи.
- URL в названии задачи и комментарии автоматически становятся кликабельными. Внешние ссылки открываются безопасно в новой вкладке.
- Шаблоны содержат название задачи и необязательную ссылку; ссылка автоматически переносится в новое списание.
- Норма дня 8 часов: меньше — красный, ровно 8:00 — зелёный, переработка — жёлтый.
- Отпуск, больничный и Day off задаются интервалами и автоматически учитываются по 8 часов в рабочие дни периода.
- Производственный календарь РФ загружается автоматически; ручные списки праздничных/рабочих дат не нужны.
- Excel-экспорт, JSON backup/restore, миграция прежних таблиц.

## Миграция
При открытии v3.2.0 приложение добавляет `taskUrl` в конец листа `Records` и `url` в конец `TaskTemplates`. Существующие данные сохраняются, ссылки необязательны. Экспорт JSON имеет формат версии 4; восстановление поддерживает старые версии 1–3.

## Производственный календарь
Приложение загружает календарь пятидневной рабочей недели РФ с `isdayoff.ru` и кэширует данные на 12 часов. Встроены резервные данные на 2024–2027 годы. Если API недоступно, используется доступный кэш или встроенный календарь. Для будущих лет без опубликованных/доступных переносов показывается предупреждение о предварительных данных.

## Google-вход и данные
- OAuth Client ID задаётся владельцем один раз в `config.js`; пользователи его не меняют.
- Данные каждого пользователя хранятся в его собственной Google Таблице.
- Действующий access token сохраняется в `sessionStorage` текущей вкладки и восстанавливается после обычной перезагрузки. После истечения/отзыва Google-токена потребуется повторный вход.
- Секреты и access tokens нельзя добавлять в публичный репозиторий.

## Публикация
1. Распакуйте `work_time_v3.2.0_release.zip`; файлы лежат в корне архива, тесты — в `tests/`.
2. Замените файлы в корне репозитория `phantasyq/worktime`, сохранив корректный `config.js`, и сделайте commit в `main`.
3. Дождитесь успешного GitHub Pages deployment и откройте сайт с `Ctrl+F5`. Service Worker использует ключ `work-time-shell-v9`.
4. Для выпуска версии откройте GitHub Releases → Draft a new release, создайте тег `v3.2.0` и приложите ZIP. Сам GitHub Release не обновляет Pages без commit в `main`.

## Проверки
Запустить: `node --test tests/*.cjs`. Покрыты производственный календарь, OAuth/session-маркеры, миграции, URL-валидация и экранирование, ссылки в шаблонах/записях, inline Jira toggle и подсветка неполных Jira-дней. Живой OAuth/Sheets flow нужно проверить на опубликованном сайте с реальной Google-конфигурацией.
