# Work Time v3.1.1 — календарь списаний

Адаптивное PWA-приложение для учёта рабочего времени на GitHub Pages с синхронизацией данных в личной Google Таблице пользователя.

## Что умеет
- Единый календарь списаний: добавление, редактирование и удаление записей из выбранной даты.
- Флаг «Списано в Jira»; сумма Jira равна длительности полностью помеченных записей.
- Шаблоны хранят только название задачи.
- Дневная норма — 8:00: меньше нормы красным, ровно 8:00 зелёным, переработка жёлтым.
- Отпуск, больничный и Day off задаются интервалами в настройках и автоматически засчитываются по 8 часов за рабочие даты интервала.
- Российский производственный календарь: выходные, нерабочие праздничные дни и рабочие субботы определяются автоматически, ручной список дат не нужен.
- Экспорт Excel и резервные копии JSON, в том числе в Drive пользователя.

## Производственный календарь
Приложение автоматически загружает календарь пятидневной рабочей недели РФ с `isdayoff.ru` и кэширует данные на 12 часов. Для календарных лет 2024–2027 встроены резервные данные с опубликованными официальными переносами, в том числе переносы 2026 и 2027 годов. Если онлайн-источник недоступен, приложение использует доступный кэш или встроенный календарь. Для будущих лет, переносы которых ещё не опубликованы/недоступны в источнике, показывается предупреждение о базовом предварительном календаре; ручной ввод дат не требуется.

## Google-вход и перезагрузка
- OAuth Client ID задаётся владельцем один раз в `config.js`; пользователи его не меняют.
- После входа короткоживущий access token сохраняется в `sessionStorage` только в текущей вкладке браузера, чтобы переживать обычную перезагрузку страницы. Токен не пишется в репозиторий и не сохраняется в `localStorage`.
- При действующей сессии после перезагрузки синхронизация запускается автоматически.
- Google access tokens имеют ограниченный срок жизни. После истечения/отзыва токена приложение попросит нажать «Войти через Google» повторно. Полностью автоматическое обновление после закрытия вкладки и истечения токена требует серверного компонента с безопасной серверной сессией/refresh token; статический GitHub Pages такого механизма не предоставляет.
- Данные пользователя хранятся в его собственном Google Drive, приложение создаёт личную таблицу и сохраняет её ID в скрытой `appDataFolder` этого же аккаунта.

## Развёртывание
1. Распакуйте архив релиза; файлы лежат сразу в корне.
2. Замените файлы в корне репозитория `phantasyq/worktime` и выполните commit в `main`.
3. Сохраните `config.js` с Client ID владельца; не добавляйте client secret или access token.
4. GitHub Pages публикуется из `main` / root. После успешного деплоя сделайте Ctrl+F5 или откройте страницу заново. Service Worker обновлён до `work-time-shell-v7`.
5. Для новых аккаунтов OAuth приложение должно быть опубликовано в Production либо пользователь добавлен в Test users на время бета-тестирования.

## Проверки
Автоматические тесты лежат в `tests/`. Запустить их можно командой `node --test tests/*.cjs`. Они проверяют даты производственного календаря, источник/кэш, синхронизацию сессии, настройку OAuth, миграции и критичные маркеры интерфейса. Живой OAuth end-to-end зависит от настроек Google Cloud и должен быть проверен на опубликованном сайте.
