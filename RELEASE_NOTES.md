# Work Time — v3.0.0

## Функциональные изменения
- Календарь стал единым экраном учёта: списания можно добавлять, редактировать и удалять из выбранного дня. Вкладка «Записи» удалена.
- В обзоре больше нет блока «По дням»; оставлены месячные метрики и последние списания.
- Jira заменена числовым полем на checkbox-флаг. В агрегатах Jira учитывается полная длительность отмеченных задач.
- Шаблон задачи содержит только название. Время, категория, Jira и комментарий задаются непосредственно в списании.
- Норма рабочего дня фиксирована на 8:00. Недобор окрашивается красным; переработка — жёлтым; точное выполнение — зелёным.
- Выходные (суббота/воскресенье) и праздничные даты блокируются для новых списаний и исключаются из нормы. Праздничные даты добавляются пользователем в «Настройки».
- В настройках добавлены интервалы отпуска, больничного и Day off. Каждый рабочий день внутри такого интервала засчитывается автоматически как 8:00. В пересекающемся интервале нельзя создать обычную запись.
- Добавлена защита от пересечения интервалов отсутствия и от добавления периода/праздника поверх уже существующих списаний.

## Совместимость и миграция
- При загрузке прежней таблицы прежнее числовое поле `jiraMinutes` мигрирует в флаг `jira`: любое положительное значение означает, что запись отмечена как Jira. Старое частичное Jira-время после миграции не сохраняется отдельно.
- Шаблоны в Google Sheets автоматически приводятся к двум столбцам: `id`, `name`.
- Старые статусы на листе `Days` превращаются в одно-дневные интервалы, после чего старый лист очищается от индивидуальных статусов.
- Резервные копии версии 1 по-прежнему можно восстановить; новая структура сохраняется в backup v2.

## Исправления
- Месячная сумма теперь учитывает только выбранный месяц и автоматически зачтённые дни отсутствия; выходные/праздники не увеличивают сумму и норму.
- Исправлен сброс выбранной календарной даты при перерисовке обзора.
- Service Worker получил новый cache key, удаляет старые кэши и использует сетевой приоритет, чтобы старый JavaScript не оставался после публикации GitHub Pages.
- Добавлен rollback состояния при ошибке сетевого сохранения записи, шаблона и настроек.

## Проверенные сценарии
1. Рабочий день с 0 часов → красный и баланс −8:00.
2. Рабочий день с ровно 8:00 → зелёный.
3. Рабочий день с 8:30 → жёлтый.
4. Суббота/воскресенье → норма 0, создать/сохранить списание нельзя.
5. Праздник из настроек → норма 0, создать/сохранить списание нельзя.
6. Рабочий день внутри отсутствия → учтено 8:00, Jira 0:00, обычное списание нельзя.
7. Отпуск/больничный/Day off не пересекаются друг с другом; рабочие записи, попадающие в интервал, должны быть перенесены/удалены до добавления интервала.
8. Старые записи Jira и шаблоны мигрируются при следующем входе.

## Важная оговорка
Автотесты синтаксиса и бизнес-логики не заменяют live end-to-end тест с OAuth и реальной Google Таблицей. Перед широким распространением нужно проверить вход, миграцию существующей таблицы и запись/перезагрузку данных в опубликованном Pages.
