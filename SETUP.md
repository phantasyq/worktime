# Публикация Work Time v3.2.0

## Обновить GitHub Pages
1. Сделайте JSON backup и/или Excel-экспорт из текущего приложения.
2. Распакуйте ZIP `work_time_v3.2.0_release.zip`.
3. Замените файлы в корне `phantasyq/worktime` файлами из архива, сохранив `config.js` с OAuth Client ID приложения.
4. Commit в ветку `main`, дождитесь успешного `github-pages` deployment.
5. Откройте `https://phantasyq.github.io/worktime/` и сделайте `Ctrl+F5`. Ключ Service Worker обновлён до `work-time-shell-v9`.

## Миграция данных
При первой загрузке v3.2.0 приложение автоматически расширяет схему Google Sheets: добавляет `taskUrl` в конец `Records` и `url` в конец `TaskTemplates`. Старые поля сохраняются, ссылки пустые, пока вы не добавите их вручную. Перед обновлением всё равно рекомендуется создать backup.

## Проверка после публикации
- Добавьте шаблон с названием и URL; сохраните, откройте ссылку на карточке.
- Используйте шаблон для создания записи и проверьте, что URL перенёсся в поле ссылки задачи.
- Введите URL в комментарии и сохраните — ссылка должна быть кликабельна в записи календаря.
- Отметьте Jira прямо в списании без открытия редактора. Проверьте, что день теряет красный Jira-индикатор только когда все его записи отмечены.
- Проверьте редактирование, удаление, backup/restore и Excel.
- Проверьте Google-вход и сохранение изменений в личной таблице.

## Тесты
На машине с Node.js выполните `node --test tests/*.cjs`. Успешный результат должен содержать 22 или больше пройденных тестов и 0 failures.

## Известные ограничения
- Ссылки поддерживают HTTP/HTTPS. Остальные схемы отклоняются.
- Внешние ссылки открываются в новой вкладке.
- OAuth и запись в Google Sheets должны быть проверены на реальном опубликованном сайте; тесты пакета не заменяют проверку Google Cloud scopes/consent screen.
