# Публикация Work Time v3.0.0

## Обновить существующий GitHub Pages сайт
1. Распакуйте `work_time_v3.0.0_release.zip`. В архиве файлы лежат сразу в корне.
2. Откройте репозиторий `phantasyq/worktime` и загрузите новые файлы поверх текущих в ветку `main` (Add file → Upload files), подтвердите commit. Не удаляйте `config.js`: Client ID вашего OAuth-приложения сохранён.
3. Убедитесь, что Settings → Pages публикует `main` из `/(root)`.
4. Дождитесь зелёного deployment `github-pages`, затем откройте сайт в инкогнито или выполните Ctrl+F5. Cache key Service Worker изменён, старые кэши будут удалены при активации новой версии.

## Создать GitHub Release
1. В репозитории откройте Releases → Draft a new release.
2. Создайте tag `v3.0.0` и название `Work Time v3.0.0 — Calendar-first time logging`.
3. В описание вставьте текст из `RELEASE_NOTES.md`.
4. При желании прикрепите этот ZIP к релизу как бинарный asset. Публикация файлов в `main` и создание Release — разные действия: ZIP сам по себе GitHub Pages не обновляет.

## После публикации проверить
- OAuth входит под существующим Google-пользователем и открывает ту же Google Sheet.
- В существующей таблице Jira-значения конвертировались из чисел в флаг, шаблоны сокращены до имени, старые статусы дней перенесены в интервалы.
- В календаре добавить запись на рабочий день, отредактировать её, включить/выключить Jira, удалить запись.
- Попробовать добавить запись на субботу/воскресенье и праздники: приложение должно отказать.
- Добавить интервал отпуска на несколько рабочих дней и проверить автоматический зачёт 8:00 в календаре/месячной норме.
- Создать запись длительностью 7:00, 8:00 и 8:30 и проверить красный, зелёный и жёлтый статусы.
- Проверить Google Drive backup, Excel export и восстановление старого JSON backup.

Праздничные даты добавляются вручную в «Настройки», чтобы приложение не предполагало страну или государственный календарь без подтверждения.
